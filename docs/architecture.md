# 寻味 1.0 项目设计

## 当前交付范围

Flask 应用工厂配合六个 Blueprint：catalog（发现与详情）、accounts（账号与个人中心）、reviews（点评）、favorites（收藏）、admin（管理）、discovery（销量榜和推荐）。模板服务端渲染，保留已验收的中文界面。Waitress 提供 Windows/Linux 通用 WSGI 启动。

## 数据与事务

- restaurants：商家信息与缓存的综合、口味、环境和服务评分。
- dishes：商家菜品、整数元价格、原有演示推荐数量。
- users：用户名、哈希密码、角色、启用状态、session_version。
- reviews：餐厅、作者、账号归属、四项评分、内容和公开/隐藏状态。
- favorites：用户和餐厅的联合主键，避免重复收藏。
- audit_logs：管理员、动作、对象编号和时间；不存密码或点评正文。
- login_attempts：哈希后的用户名/IP 标识、失败次数、计数起始时间。
- app_meta：演示数据初始化标记。
- daily_sales：餐厅/日期联合主键，保存每日完成订单总量、录入/演示来源和更新时间；按日期建立索引。版本 2 在版本 1 的基础上新增此表，升级前自动备份。

SQLite 开启外键，每次请求独立连接、结束时关闭。业务修改和相关操作日志在同一事务提交。所有值通过 SQL 参数绑定；排序字段与统计表名由代码白名单决定。金额当前按整数元保存。

旧库采用追加字段和表的迁移，PRAGMA user_version 标记版本。升级前以 SQLite backup API 创建一致性副本；备份失败则终止升级。未来每个结构变更都应新增版本步骤，不能只修改当前版本号。迁移和服务启动应作为单实例操作执行。

## 账号与权限

普通用户只能修改、删除自己的点评；匿名历史点评没有可认领账号。管理员可管理所有点评、餐厅、菜品和用户。
会话记录账号 ID 与 session_version。修改密码或切换启用状态会递增版本，使旧会话失效。
写请求校验 CSRF；测试模式不会自动绕过，旧回归测试显式关闭，新项目测试保持开启。
登录失败按用户名 10 次/IP 50 次限制在 15 分钟窗口内。该机制用于当前单服务部署，尚未接入外部防滥用系统。

## 业务规则

点评发布后直接展示；管理员可以隐藏或恢复。所有评分、分布和公开点评数均来自公开点评；无公开点评时评分为零。修改被隐藏的点评不会自动恢复公开。
收藏先按用户或游客提供的本地 ID 集合过滤，再分页。登录后通过幂等接口合并本地收藏；只有成功响应后才清理本地数据。
新安装默认不创建账号；管理员通过 CLI 交互创建。演示数据只在显式指定 --demo 时导入。

## 明确未包含

在线支付、订单、定位地图、用户图片上传、短信邮件找回密码、商家入驻、多节点部署和真实商家数据采集尚未实现。这些需要后续明确业务规则及第三方服务配置。
